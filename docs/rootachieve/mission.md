# Mission 구현 기록

## 학생 미션 실제 진행률 및 관련 화면 레이아웃 수정 (#198)

- 학생 홈 진행률이 `1 / 3`으로 복구되던 원인은 `studentTripApi`의 고정값과 제출 후 로컬 증가 로직이었다. 고정값·로컬 증가를 제거하고, 학생 미션 개요 응답의 `completedCount`와 `totalCount`를 최초 진입·제출 직후·기존 폴링에서 동일하게 반영하도록 바꿨다.
- `GET /api/trips/{tripId}/missions/overview`는 시작 시각이 지난 미션만 전체 개수에 포함하고, 해당 학생의 `COMPLETED`·`LATE` 제출을 완료로 집계한다. 완료·지각 제출 및 교사가 완료한 미션은 현재 수행 목록에서 제외한다.
- 학생 현재 미션에 이미 있던 `setInterval`의 주기만 `20_000`에서 `1_000`으로 변경했다. 수동 새로고침 버튼이나 다른 화면의 폴링은 추가하지 않았다.
- 학생 초대 코드 입력은 고정 폭과 바깥 여백을 없애 320px 화면 안에서 여섯 칸이 유동적으로 줄어들게 했다. 교사 초대 코드는 기존 flex 컨테이너 안에서 가운데 정렬하고, 미션 상태·체험학습 상세의 연속 버튼에는 12px 간격을 적용했다.
- API 응답과 완료·예약·비참가자 경로, 앱 재실행 시 진행률 복구, 1초 뒤 현재 미션·진행률 갱신을 회귀 테스트로 고정했다.

검증: `cd backend && ./gradlew test`, `cd frontend && npm test`(42파일 281개), `npm run lint`, `npm run build`, 320px 브라우저 렌더링(가로 overflow 없음, 초대 코드 중심 오차 0px, 버튼 간격 12px, 콘솔 오류 없음), `git diff --check` 통과.
